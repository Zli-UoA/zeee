SmartHR Design System の「情報設計のアウトプット」に沿って、Zeee の RC 向け情報設計を 5 種類の成果物として整理する。ここで決めるのは情報の構造・名前・関係性であり、色、余白、コンポーネント、モーションは対象外。

## 対象プロダクト

Zeee は Zli のメンバー向けの Markdown 知識ベース。ログインした全員が全ページを閲覧・編集できる。ページは `/` 区切りのパスを表示名に持ち、ディレクトリはページのパスから導出される。

```text
Zeee
├─ Page（ページ）        Markdown 文書。パスが表示名。葉。
├─ Directory（ディレクトリ） Page のパスから導出されるスコープ。保存 Entity ではない。
├─ Revision（版）        Page 本文の保存時点。自動・手動がある。
└─ User（ユーザー）      Zli メンバー。全ページを編集できる。
```

## 決定事項（ドラフト）

| #   | 論点                     | 決定                                                                                                   | 理由                                                               |
| --- | ------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 1   | `Spaces`                 | 採用しない                                                                                             | 既存の `Directory` と同じものを別名で呼ぶことになるため            |
| 2   | `Directory`              | Page のパスから導出するスコープ。保存 Entity にしない                                                  | 既存のパス方式を維持し、空ディレクトリや一括 rename を持ち込まない |
| 3   | ルート画面               | `すべてのページ`（`/`）。`Home` は置かない                                                             | 小規模 wiki では Home と All pages の重複が大きいため              |
| 4   | 検索                     | グローバルヘッダーの検索 + `⌘K`。結果一覧は `/?q=`                                                     | 検索は全ページ横断の機能で、画面固有ではないため                   |
| 5   | 最近見たページ           | サイドバーに最大 5 件。検索パレットの空状態にも表示。専用ページは作らない                              | 階層ではなくショートカットなので、主ナビと分ける                   |
| 6   | 新規ページ               | 常設の `+`。初期値は現在の文脈から決める                                                               | グローバル操作とディレクトリ文脈の両方を成立させるため             |
| 7   | ヘッダー                 | グローバルヘッダーはブランド・検索・新規・アカウント。ページのパンくず・ページ名・操作はページヘッダー | グローバル操作とページ固有の文脈を混ぜないため                     |
| 8   | 目次・バックリンク・履歴 | 目次とバックリンクはページのサイドパネル、履歴は別パネル。独立したナビにはしない                       | ページを読む/編集する文脈から切り離さないため                      |
| 9   | 権限                     | ログインユーザー全員が全ページを編集。ページ単位 ACL は扱わない                                        | 現行 RC のスコープを維持するため                                   |
| 10  | 用語                     | UI / IA では「パス」に統一する。`title` は API / DB の実装名として残す                                 | 同じものを別名で呼ばないため                                       |
| 11  | すべてのページ           | 本文は一覧、階層はサイドバーのページツリーとパンくずで辿る。Directory 本文も一覧                       | 一覧とツリーの役割を分け、同じ画面に 2 つの主役を置かないため      |
| 12  | 新規ページの初期値       | 入力途中の prefix（例: `a/b/`）を許す。保存は最後のセグメントを入れるまで不可                          | 文脈を引き継ぎつつ、無効なパスを保存させないため                   |
| 13  | 検索の 2 画面            | パレットは上位 5 件、`/?q=` は全件。`q` が `dir` より優先                                              | パレットの軽さと、結果を絞り込む一覧の両方を残すため               |
| 14  | 削除後の遷移             | ゴミ箱へ移動し、復元導線を見せる                                                                       | 削除の結果と取り消し導線を同じ場所で示すため                       |
| 15  | 履歴とサイドパネル       | 排他。履歴は閲覧/編集の両方から開ける。履歴行は「差分を見る」、復元はプレビュー内で行う                | 本文の幅を確保し、破壊的な復元をプレビュー経由にするため           |
| 16  | フラット面のラベル       | ツリーは末尾セグメント、フラットな一覧はフルパス。検索結果・Recent・Trash も同じ規則                   | 同名の葉を区別し、現在地を見失わないため                           |
| 17  | アカウントメニュー       | RC ではログアウトだけを置く。プロフィール画面は作らない                                                | アカウント管理のスコープを広げず、認証操作だけに絞るため           |

## 用語

| 用語                       | 定義                                                                         | 使わない語                                    |
| -------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------- |
| Page / ページ              | パスを表示名に持つ Markdown 文書。ページは葉で、子ページを持たない           | Document、ノート                              |
| Directory / ディレクトリ   | active Page のパスから導出されるスコープ。実体・ID・ライフサイクルを持たない | Space、Folder、Root pages                     |
| Path / パス                | ページのフルパス。`a/b/c` の形式。UI / IA では「パス」に統一する             | タイトル（UI / IA の表示名としては使わない）  |
| Page name / ページ名       | パスの末尾セグメント。ツリーやページヘッダーで表示する派生表示名             | タイトル                                      |
| Revision / 版              | ページ本文の保存時点。自動保存と手動保存がある                               | バージョン、スナップショット（UI では「版」） |
| History / 履歴             | Revision の一覧と復元を扱うビュー。閲覧/編集の両方から開ける                 | 変更ログ                                      |
| Trash / ゴミ箱             | 削除済み Page を表示するビュー。独立した Entity ではない                     | アーカイブ                                    |
| Recent / 最近見たページ    | ユーザーごとの閲覧履歴。最大 5 件をサイドバーに出すショートカット            | Recents ページ                                |
| All pages / すべてのページ | ルートのページ一覧ビュー。本文は一覧、階層はサイドバーのツリー               | Home、Browse、Root pages                      |
| Search / 検索              | 全ページ横断の検索。パレットは上位 5 件、結果一覧は全件                      | ディレクトリ内検索（MVP 外）                  |
| New page / 新規ページ      | ページを 1 つ作成するアクション。パス入力ダイアログを開く                    | 新規 Space、新規ディレクトリ                  |

API / DB の `title` は実装名として残す。UI / IA では「パス」と呼ぶ。

## 現状との差分

この IA は `9361bbc` の実装を前提にしたドラフトだが、次の点は実装と差分がある。

| 項目                           | 現状                                             | この IA の目標                                                  |
| ------------------------------ | ------------------------------------------------ | --------------------------------------------------------------- |
| グローバルヘッダー             | パンくずとページ名も表示する                     | ブランド・検索・新規・アカウントだけにする                      |
| ページヘッダー                 | ページ名と操作が本文側にある                     | パンくず・ページ名・ページ操作をページヘッダーにまとめる        |
| `/` の名前                     | 「ページ」                                       | 「すべてのページ」                                              |
| サイドバーの「すべてのページ」 | グループラベル                                   | グループラベル + ルートへのリンク                               |
| 新規ページ                     | 常に空のパス入力                                 | ディレクトリ・ページ・検索・Wiki リンクの文脈から初期値を決める |
| モバイルの検索                 | ヘッダーのパレットと `/` の検索フォームが併存    | 検索入口をグローバルヘッダーに一本化する                        |
| ページ閲覧時のページ名         | 末尾セグメントのみ。パンくずはグローバルヘッダー | ページヘッダーにパンくず + ページ名をまとめる                   |
| ゴミ箱の復元失敗               | 409 の理由を十分に表示しない                     | パス衝突を説明し、自動 rename しない                            |
| サイドバー初期状態             | 開いた状態で始まる場合がある                     | UI 契約で決める（この IA の対象外）                             |
| ページ遷移アニメーション       | 遷移ごとに開閉アニメーションがある               | UI 契約で「移動時はアニメーションしない」を決める               |

## 未決事項

IA の新規未決はない。以下は決定済みとしてレビューで確認する。

- Directory は概念モデルにだけ残し、オブジェクトモデルには含めない
- すべてのページとディレクトリの本文は一覧。階層はサイドバーのツリーとパンくずで辿る
- ツリーは末尾セグメント、フラットな一覧はフルパスで表示する
- 履歴は閲覧/編集の両方から開け、目次/バックリンクと排他にする
- 新規ページの初期値は入力途中の prefix。保存は完全なパスで行う
- 削除済みページの「ページがない」画面にはゴミ箱への導線を出す

UI 契約で決めること（IA の対象外）。

- サイドバーの初期開閉状態とブレークポイント
- ページ遷移時のアニメーション
- 目次パネルの見た目（左レール / タブ / シート）
- 履歴パネルの見た目（右シート / インライン）
- モバイルでページサイドパネルと履歴パネルを同じシートにするか、別のシートにするか
- 並び順の選択 UI と日付グループの見た目
- Kumo コンポーネントの選定と余白
