SmartHR Design System の「情報設計のアウトプット」に沿って、Zeee の RC 向け情報設計を 5 種類の成果物として整理する。ここで決めるのは情報の構造・名前・関係性であり、色、余白、コンポーネント、モーションは対象外。

## 対象プロダクト

Zeee は Zli のメンバー向けの Markdown 知識ベース。ログインした全員が全ページを閲覧・編集できる。ページは `/` 区切りのパスをタイトルに持ち、ディレクトリはページのパスから導出される。

```text
Zeee
├─ Page（ページ）        Markdown 文書。パスがタイトル。葉。
├─ Directory（ディレクトリ） Page のパスから導出されるグループ。保存 Entity ではない。
├─ Revision（版）        Page 本文の保存時点。自動・手動がある。
└─ User（ユーザー）      Zli メンバー。全ページを編集できる。
```

## 決定事項（ドラフト）

| #   | 論点                     | 決定                                                                                                   | 理由                                                               |
| --- | ------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 1   | `Spaces`                 | 採用しない                                                                                             | 既存の `Directory` と同じものを別名で呼ぶことになるため            |
| 2   | `Directory`              | Page のパスから導出するグループ。保存 Entity にしない                                                  | 既存のパス方式を維持し、空ディレクトリや一括 rename を持ち込まない |
| 3   | ルート画面               | `すべてのページ`（`/`）。`Home` は置かない                                                             | 小規模 wiki では Home と All pages の重複が大きいため              |
| 4   | 検索                     | グローバルヘッダーの検索 + `⌘K`。結果一覧は `/?q=`                                                     | 検索は全ページ横断の機能で、画面固有ではないため                   |
| 5   | 最近見たページ           | サイドバーに最大 5 件。検索パレットの空状態にも表示。専用ページは作らない                              | 階層ではなくショートカットなので、主ナビと分ける                   |
| 6   | 新規ページ               | 常設の `+`。初期パスは現在の文脈から決める                                                             | グローバル操作とディレクトリ文脈の両方を成立させるため             |
| 7   | ヘッダー                 | グローバルヘッダーはブランド・検索・新規・アカウント。ページのパンくず・タイトル・操作はページヘッダー | グローバル操作とページ固有の文脈を混ぜないため                     |
| 8   | 目次・バックリンク・履歴 | 目次とバックリンクはページのサイドパネル、履歴は別パネル。独立したナビにはしない                       | ページを読む/編集する文脈から切り離さないため                      |
| 9   | 権限                     | ログインユーザー全員が全ページを編集。ページ単位 ACL は扱わない                                        | 現行 RC のスコープを維持するため                                   |
| 10  | 用語                     | `Page` / `Directory` / `Revision` / `Trash` / `Recent` を UI でも API でも同じ意味で使う               | 同じものを別名で呼ばないため                                       |
| 11  | すべてのページ           | 本文側は更新順の一覧。階層はサイドバーのページツリーで辿る                                             | 一覧とツリーの役割を分け、同じ画面に 2 つの主役を置かないため      |
| 12  | 新規ページの初期パス     | ページから作成する場合は親ディレクトリを初期値にする                                                   | 現在のページの兄弟を作る操作が最も自然なため                       |
| 13  | 検索の 2 画面            | 検索パレットはクイック検索、`/?q=` は全結果一覧                                                        | パレットの軽さと、結果を絞り込む一覧の両方を残すため               |
| 14  | 削除後の遷移             | ゴミ箱へ移動し、復元導線を見せる                                                                       | 削除の結果と取り消し導線を同じ場所で示すため                       |
| 15  | 履歴とサイドパネル       | 排他。履歴を開くと目次/バックリンクを閉じ、右の補助領域を切り替える                                    | 本文の幅を確保し、2 つの補助情報を同時に詰め込まないため           |

## 用語

| 用語                       | 定義                                                                   | 使わない語                                    |
| -------------------------- | ---------------------------------------------------------------------- | --------------------------------------------- |
| Page / ページ              | パスをタイトルに持つ Markdown 文書。ページは葉で、子ページを持たない   | Document、ノート                              |
| Directory / ディレクトリ   | ページのパスから導出されるグループ。実体・ID・ライフサイクルを持たない | Space、Folder、Root pages                     |
| Path / パス                | ページのフルパス。`a/b/c` の形式。ページの表示名を兼ねる               | タイトル（別名として使わない）                |
| Revision / 版              | ページ本文の保存時点。自動保存と手動保存がある                         | バージョン、スナップショット（UI では「版」） |
| History / 履歴             | Revision の一覧と復元を扱うビュー                                      | 変更ログ                                      |
| Trash / ゴミ箱             | 削除済み Page を表示するビュー。独立した Entity ではない               | アーカイブ                                    |
| Recent / 最近見たページ    | ユーザーごとの閲覧履歴。最大 5 件をサイドバーに出すショートカット      | Recents ページ                                |
| All pages / すべてのページ | ルートのページ一覧ビュー。ページツリーの起点                           | Home、Browse、Root pages                      |
| Search / 検索              | 全ページ横断の検索。パレットと結果一覧がある                           | ディレクトリ内検索（MVP 外）                  |
| New page / 新規ページ      | ページを 1 つ作成するアクション。パス入力ダイアログを開く              | 新規 Space、新規ディレクトリ                  |

## 現状との差分

この IA は `9361bbc` の実装を前提にしたドラフトだが、次の点は実装と差分がある。

| 項目                           | 現状                                             | この IA の目標                                                  |
| ------------------------------ | ------------------------------------------------ | --------------------------------------------------------------- |
| グローバルヘッダー             | パンくずとページ名も表示する                     | ブランド・検索・新規・アカウントだけにする                      |
| ページヘッダー                 | ページ名と操作が本文側にある                     | パンくず・ページ名・ページ操作をページヘッダーにまとめる        |
| `/` の名前                     | 「ページ」                                       | 「すべてのページ」                                              |
| サイドバーの「すべてのページ」 | グループラベル                                   | グループラベル + ルートへのリンク                               |
| 新規ページ                     | 常に空のパス入力                                 | ディレクトリ・ページ・検索・Wiki リンクの文脈から初期値を決める |
| モバイルの検索                 | ヘッダーのパレットと `/` の検索フォームが併存    | 検索入口をグローバルヘッダーに一本化する                        |
| ページ閲覧時のタイトル         | 末尾セグメントのみ。パンくずはグローバルヘッダー | ページヘッダーにパンくず + 末尾セグメントをまとめる             |
| ゴミ箱の復元失敗               | 409 の理由を十分に表示しない                     | パス衝突を説明し、自動 rename しない                            |
| サイドバー初期状態             | 開いた状態で始まる場合がある                     | UI 契約で決める（この IA の対象外）                             |
| ページ遷移アニメーション       | 遷移ごとに開閉アニメーションがある               | UI 契約で「移動時はアニメーションしない」を決める               |

## 未決事項

IA のレビューで決めること。

1. ページがない場合に、ゴミ箱への導線を常に出すか。
2. モバイルでページサイドパネルと履歴パネルを同じシートにするか、別のシートにするか。

UI 契約で決めること（IA の対象外）。

- サイドバーの初期開閉状態とブレークポイント
- ページ遷移時のアニメーション
- 目次パネルの見た目（左レール / タブ / シート）
- 履歴パネルの見た目（右シート / インライン）
- Kumo コンポーネントの選定と余白
- アカウントメニューにログアウト以外の項目を置くか
